## 最短获奖路径

严格按以下顺序推进，Dashboard、MCP 和复杂 UI 暂停：

1. Hosted Registry：查询、下载、发布、SHA-256 校验。
2. 用增强版 cjpm 完成“公共包 + 私有包”真实构建闭环。
3. Proxy：首次 MISS、二次 HIT、上游离线仍可构建。
4. 增量 Sync / Mirror：至少完成一个可重复的仓到仓场景。
5. Docker Compose 一键部署，并在干净环境复验。
6. Override、来源记录和官方回归测试补齐。
7. 最后制作 Benchmark、攻击防护演示、视频和答辩材料。

## 粗略工作量

| 目标 | 还需投入（集中开发） |
| --- | ---: |
| 可运行、可提交的官方要求 MVP | 约 5–8 个有效开发日 |
| 有说服力的决赛/获奖版本 | 约 12–20 个有效开发日 |
| 对一等奖/二等奖有强竞争力的完成度 | 约 25–40 人日，并需要真实用户反馈与演示打磨 |

工作量会被仓颉 HTTP/文件 API 的成熟度、官方仓协议细节、完整测试环境是否顺利显著影响。当前应以“官方四项全部有真实证据”为第一目标，不以功能数量为目标。
