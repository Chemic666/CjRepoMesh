# CjRepoMesh 参赛提交检查表

> 用法：最终提交前逐项核对；未完成项不能在报名材料中写成已完成。

## A. 官方要求闭环

- [ ] 多仓配置、优先级和旧 `repository.home` 兼容测试在最终提交通过；
- [ ] 跨仓版本聚合后仍由原 cjpm 求解器选择版本；
- [ ] 同版本来源冲突、`[replace]`、404/5xx 回退和 401/403 阻断有证据；
- [ ] 私有中心仓能够由一条命令部署、诊断、停止和持久化重启；
- [ ] Hosted 发布、索引、下载、鉴权、SHA-256 和重复版本行为通过；
- [ ] Proxy MISS/HIT、TTL、离线命中、并发填充和损坏拒绝通过；
- [ ] 批量 Mirror 与批量 CjRepo-to-CjRepo Sync 通过；
- [ ] 完整五组端到端测试在最终提交号上连续通过。

## B. 代码与仓库卫生

- [ ] `git status --short` 为空；
- [ ] 不提交 SDK、编译产物、缓存、Token、PID、日志或测试临时数据；
- [ ] README 第一屏能看见项目定位、官方课题和验证入口；
- [ ] LICENSE、版权头和第三方来源说明完整；
- [ ] 所有文档链接和相对路径有效；
- [ ] 默认配置不包含真实企业地址或凭据；
- [ ] 最终 Tag/提交号已记录，AtomGit 仓库可匿名读取；
- [ ] 比赛平台填写的仓库地址指向参赛仓，而不是官方上游仓。

## C. 验证材料

- [ ] `docs/verification-report.md` 使用最终提交号和最终一次真实耗时；
- [ ] `benchmark/results/proxy-benchmark.json` 保留原始样本；
- [ ] Benchmark Markdown 与 JSON 结果一致；
- [ ] Windows 一键部署在干净数据目录重新验证；
- [x] WSL 2 / Ubuntu 22.04 Linux 原生基线已记录在 `docs/linux-verification.md`；
- [x] Linux 四组共享核心统一入口已在提交 `3fee985` 上 4/4 通过；
- [x] Docker 基础镜像摘要、命令、持久化和安全诊断已记录在 `docs/docker-verification.md`；
- [ ] 基于最终提交重跑 Linux 与 Docker 关键链路；
- [ ] 未运行完整 Maple HLT/LLT 时继续明确标注，不写“全部官方测试通过”；
- [ ] 所有测试结束后无遗留服务监听测试端口。

## D. 安全与表述

- [ ] Dependency Confusion 演示证明公共仓请求数为 0，而不只是最终版本正确；
- [ ] 401/403 演示证明不会回退公共仓；
- [ ] Token 仅来自环境变量，不出现在录屏命令历史和提交文件；
- [ ] `cjpm-provenance.json` 明确称为独立审计文件，不冒充官方 lockfile；
- [ ] Mirror 明确称为显式清单镜像，不宣称完整复制官方中心仓；
- [ ] 性能数字注明机器、轮次、本地 HTTP 场景和限制；
- [ ] 不以关闭系统安全策略作为构建或演示步骤。

## E. 视频与答辩

- [ ] 按 `docs/demo-runbook.md` 完成 6～8 分钟主视频；
- [ ] 同时保留一份完整无剪切验证视频；
- [ ] 开场 40 秒内说清“Router 与原求解器分层”；
- [ ] 至少现场展示一键部署、多仓兼容、安全边界、Proxy 离线、Mirror/Sync；
- [ ] 展示 Explain/Doctor，而不是只展示 `BUILD SUCCESS`；
- [ ] 所有字幕、终端字体和架构图在 1080p 下可读；
- [ ] 准备断网、端口占用、SDK 阻断和 Benchmark 波动的保底切换；
- [ ] 答辩结尾如实说明 organization、读鉴权、调度、断点续传和 Linux/Docker 边界。

## F. 提交前最后 30 分钟

- [ ] 从比赛页面重新确认截止时间、材料格式和仓库可见性要求；
- [ ] 用无登录浏览器打开 AtomGit 仓库、视频和附件链接；
- [ ] 校验提交平台上的项目名、课题编号、成员、联系方式和开源协议；
- [ ] 下载或截图提交成功回执；
- [ ] 截止前保留缓冲，不在最后 30 分钟改代码或重录视频。
